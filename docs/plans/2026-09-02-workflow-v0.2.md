# Frontend SDD Workflow v0.2 实施计划

> 历史计划：Worktree 实现已在后续真实项目执行方案中移除，保留本文用于记录方案演变。

**目标：** 实现多 Skills 全量分发、Workspace 隔离 Worktree 关联，以及不回退状态的产物一致性传播。

**架构：** 安装器只负责复制和校验仓库资产；`.ai-dev/scripts` 负责可重复的 Git/状态操作；`prd-to-code` Skill 和工作流文档负责要求 Agent 在正确节点调用这些脚本。业务项目的框架、版本和命令继续由 Agent 从仓库证据中判断。

**技术栈：** Node.js 18+、Node Test Runner、Git Worktree、Agent Skills。

**设计依据：** `docs/decisions/2026-09-02-workflow-v0.2.md`

## 全局约束

- 不增加框架 Profile、项目类型配置或业务项目兼容版本矩阵。
- 不限制 Skill 自动触发，也不让员工选择安装哪些 Skills。
- 不自动创建 PR，不自动 push、merge 或 deploy。
- 新行为先写失败测试，再写最小实现。

## Task 1：多 Skills 全量分发

**文件：**

- 修改：`test/installer.test.mjs`
- 修改：`src/installer.mjs`
- 修改：`package.json`

**步骤：**

1. 在测试夹具中加入第二个 Skill，断言 `install` 和 `setup` 都复制两个 Skill。
2. 运行 `node --test test/installer.test.mjs`，确认测试因安装器硬编码而失败。
3. 将安装来源提升为 `.agents/skills` 根目录，并让 `doctor` 检查全部直接子目录的 `SKILL.md`。
4. 将 npm 发布文件从单个 Skill 改为整个 `.agents/skills`。
5. 重跑安装器测试并确认通过。

## Task 2：Workspace 隔离 Worktree

**文件：**

- 创建：`template/.ai-dev/scripts/init-worktree.mjs`
- 创建：`template/.ai-dev/templates/worktree.json`
- 创建：`template/.ai-dev/templates/code-change.md`
- 创建：`template/.ai-dev/gitignore.template`（安装时映射为 `.ai-dev/.gitignore`，避免 npm 忽略该文件）
- 创建：`test/worktree.test.mjs`
- 修改：`template/.ai-dev/scripts/validate-change.mjs`

**步骤：**

1. 创建临时 Git 仓库和需求 Workspace，测试默认分支、Worktree 路径、软链与元数据。
2. 运行测试并确认脚本不存在导致失败。
3. 实现 `init-worktree.mjs`，只处理 Git 隔离和记录，不安装依赖、不识别框架。
4. 将 Worktree 元数据和代码变更记录加入新需求模板与校验范围。
5. 重跑 Worktree 和初始化测试。

## Task 3：产物一致性传播

**文件：**

- 创建：`template/.ai-dev/artifact-graph.json`
- 创建：`template/.ai-dev/scripts/update-consistency.mjs`
- 创建：`test/consistency.test.mjs`
- 修改：`template/.ai-dev/templates/status.json`
- 修改：`template/.ai-dev/scripts/validate-change.mjs`

**步骤：**

2. 测试 `resolve` 仅清除已经刷新的产物。
3. 测试审核状态存在过期产物时校验失败。
4. 运行测试并确认新行为尚不存在。
5. 实现最小脚本和校验逻辑，重跑相关测试。

## Task 4：工作流接入和文档收敛

**文件：**

- 修改：`.agents/skills/prd-to-code/SKILL.md`
- 修改：`template/.ai-dev/workflow.md`
- 修改：`template/.cursor/rules/prd-to-code.mdc`
- 修改：`README.md`
- 删除：旧的外部方法论设计和计划文档目录

**步骤：**

1. 让 Skill 在计划批准后创建 Worktree，并在产物变更时执行一致性标记/刷新。
2. 更新工作流和 Cursor 规则，明确代码仅在 Workspace 的 `project` 软链目标中修改。
3. 更新一键安装说明为全量 Skills，同步说明 Worktree 不产生 PR。
4. 删除外部项目专属目录和产品文档表述。
5. 搜索仓库，确认不存在外部项目名称或不在范围内的 Profile/版本设计。

## Task 5：完整验证

1. 运行 `npm test`。
2. 在临时目录执行 `doctor`、`install` 和 `setup` 冒烟测试。
3. 校验 `prd-to-code` Skill 的 frontmatter 和目录结构。
4. 检查 `git diff --check`、`git status` 和最终差异范围。
