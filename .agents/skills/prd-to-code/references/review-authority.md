# 审核结果与放行

人不用喊「去审」。主 Agent 做完任务后，由宿主自动唤起子 Agent。人只在**子 Agent 写了「无法确定」**时被打扰。

## 子 Agent 必须交出来的东西

每一份审核都要同时有这三项（`summary.md`）：

1. **审核了哪些**：检查项 / FR / AC / 文件位置
2. **每一项结果**：通过 / 未通过 / 无法确定
3. **总结论和原因**
   - 通过：可以放行该任务
   - 未通过：规则已明确，实现没达到，回主 Agent 改
   - 无法确定：缺产品依据，**必须把原因告诉用户**

## 审完之后发生什么（事件）

| 总结论 | 抛给谁 | 主 Agent 做什么 |
| --- | --- | --- |
| 通过 `review.passed` | 主 Agent | `accept` 后立刻 `next`（例如做 T2） |
| 未通过 `review.returned` | 主 Agent | 按原因改代码或补证，再自动复审，**不要喊人** |
| 无法确定 `review.needs_human` | **用户** | 停住，把「缺什么、选项、影响」说给人听，**不得代决** |

「无法确定」只包括：PRD/契约没写清且影响能不能验收、来源打架、职责/权限超出本仓库。  
「文件在哪、测试跑了没、这个 AC 做了没」不是无法确定，子 Agent 自己查或退回主 Agent。

## 人还要点头的，只有这些

整单需求的 **scope**（做不做、前后端归谁）和 **final**（整单能不能收工），以及上面的「无法确定」。  
子 Agent 通过 **不能** 代替 commit / PR / 发布。

## 谁唤起子 Agent（不要等人打字）

1. 任务变成 `review_pending` 后，主 Agent 必须立刻 Task/spawn `sdd-reviewer`。
2. 若主 Agent 停下来还没派：Cursor `stop` hook 自动插入一条 follow-up（看起来像系统又提了一次），**每个任务只插一次**。
3. 用户说「用 reviewer 审」只是备用，不是主路径。
