# 验收截图与对话可读性

## 1. 需求目标

2026-11-16 用户在 Cursor 实测后反馈：测试结束应在固定本地目录留下截图供人 review；对话中测试触发、过程和结果的感知与可读性不足。目标是让开发者能核对测了什么、预期与实际是否相符。

## 2. 已确认的业务规则

- 沿用任务 DONE 交审前与 VERIFYING 最终候选重跑的触发点，不增加审批阶段。
- 自动测试应提供本地截图与可读报告。Mock、真实接口、工程检查、人工验收分开说明。
- 图片辅助复核，不替代业务断言；失败、受阻、缺数据、未执行和过期不能宣称通过。
- 对话要说明何时开始、环境与场景、实际结果和未测项，不只输出 runId 或 Reviewer pass。

## 3. 技术实现

- `template/.ai-dev/scripts/lib/visual-evidence.mjs` 提供 `captureAcceptanceScreenshot`，兼容 Playwright/ego-browser 的绝对路径 PNG 截图；`collectVisualEvidence` 校验逐预期 screenshotRefs 的文件、格式、当前运行与用例归属。
- 新运行记录标记 visualEvidenceVersion=1。UI/navigation 通过预期缺图会失败；截图纳入 record.files 指纹，后续改写令证据无效。旧记录维持原契约，不伪造旧截图。
- `acceptance-report.mjs` 生成每轮 report.html；`acceptance.mjs` 刷新固定入口 artifacts/verification/index.html。截图保存在 revisions/verifications/<runId>/screenshots/<caseId>/，重跑不覆盖旧证据。
- 执行器 CLI 输出开始、30 秒运行中提示和结束汇总，stdout 保持 JSON；四个相关 Skills 补充对话说明、截图采集、审核材料与缺口披露。
- prepare-review 契约要求新记录引用的用例截图在审核包内。RAG/摘要等候选文件必须在最终测试前更新，批准后不再为修改阶段文案变更候选。

## 4. 重要决策

- 使用当前 run 输出目录，避免截图/报告反过来改变源码快照；总览是可刷新阅读视图，每轮报告和图片封存。
- 项目 Agent 根据实际断言位置调用采集函数，不让用户逐张截图或手配业务规则。未执行的历史状态不能补拍冒充。
- 保留旧记录兼容，新增截图要求只作用于新执行器产生的视觉证据版本；COMPLETE 历史需求不自动重开。
- 通用渲染器不翻译或替模型推断观察内容；测试作者需要提供具体业务观察。

## 5. 待确认问题与限制

- 用户已授权将本次工作流改动提交推送，发布版本以 Git 提交及远程分支记录为准；尚未安装到 enterprisewechat。旧业务需求的弱断言、遗漏和过期结项仍须在该项目按实际范围修复并重跑，本轮没有替其生成通过证据。
- 图片内容不能由格式/指纹证明；敏感内容需采集前使用测试数据、遮罩或区域截图，文字脱敏不等于图片脱敏。
- 对话约定已写入 Skills，真实 Cursor 后续需求中的遵循情况仍需观察；脚本输出不保证宿主会逐字转述。
