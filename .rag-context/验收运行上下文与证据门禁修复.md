## 1. 需求目标

让不同前端项目可以复用自己的启动、登录、入口参数和测试数据规则，并确保“通过”对应实际完成的业务断言。以 enterprisewechat 0921 群发需求验证，不替用户最终验收批准。

## 2. 已确认的业务规则

- 主应用是可选依赖，普通项目、URL path/query/hash 参数、登录态和数据前提均应支持。
- Agent 自动查找和绑定有来源的测试数据；缺失且不可获取时请求具体信息，不猜 ID。
- 前置条件未满足、仅空态或仅静态代码检查不能证明完整运行行为。
- 登录确认不是人工验收确认；浏览器自动操作需保存运行和逐项断言证据。
- 企微试点：本地 xiaolv 主应用 + enterprisewechat 预发；使用用户提供的 onelogin-beta 模拟代理登录入口，用户扫码并选择有数据账号。

## 3. 技术实现

- `test-runtime.mjs` 支持可选依赖服务、登录前提、path/query/hash 参数来源、缺参反例、敏感参数脱敏与当前配置证据。
- `case-evidence.mjs`、`verification-report.mjs` 与独立审核契约核对每条前提和预期；browser-json 接入真实 Ego 脚本；manual 需有理由及实际确认；inspection 只证明文档/源码事实。
- `verification.mjs` 保存当前候选的原始报告，区分纯准备阻塞和真正失败；混合失败不能被 blocked 覆盖。最终人工批准规则保留。
- acceptance-testing、prepare-review、review-delivery、prd-to-code Skills 已同步；新增门禁反例、独立订单详情生成试跑及 enterprisewechat 浏览器用例。
- enterprisewechat 增加 tests/acceptance 运行配置、合约 fixture、网络拦截与重复执行入口。业务源码未在本轮修改；旧人工记录保留但不复用为新 browser 用例通过证据。
- 最终回归164项通过；真实前端合约验收11例、56项断言通过；错误科目隔离反例失败符合预期。live 保持 blocked、人工视觉 pending，工作区材料已同步且无 stale 项。
- 收尾修复 blocked 在汇总中丢失的问题，以及中文路径/重命名旧路径的变更清单识别，均补反例验证。
